# LDAP и Active Directory

> [!abstract] Кратко
> LDAP — протокол доступа к службам каталогов (порты 389/636). Active Directory (AD) — проприетарная реализация LDAP от Microsoft для централизованного управления пользователями, компьютерами и политиками безопасности в домене. Ключевой компонент корпоративной инфраструктуры и главная цель атак на учетные данные (Kerberoasting, DCSync, Pass-the-Hash).

## 1. Зачем нужно
В корпоративной сети сотни пользователей и компьютеров. Держать локальные учетки на каждой машине — ад. AD позволяет создать единую базу (каталог), где хранятся все учетные записи и права. Пользователь вводит пароль один раз и получает доступ ко всем ресурсам домена (SSO). Аналитику SOC нужно знать, как устроен этот каталог, чтобы понимать логи аутентификации и видеть атаки на них.

## 2. Простыми словами
**LDAP** — это «язык запросов» к базе данных пользователей. Как SQL, но для директорий. Ты говоришь: «Найди мне пользователя с именем Вася», и LDAP возвращает его атрибуты (телефон, отдел, права).
**Active Directory** — это сама база данных от Microsoft, которая «говорит» на этом языке. Внутри неё всё разложено по полочкам: домены, деревья, леса, организационные подразделения (OU). Контроллер домена (DC) — это сервер, который хранит эту базу и проверяет пароли.

## 3. Технические детали

### 3.1. Порты LDAP
- **389 (TCP/UDP):** Стандартный LDAP. Трафик не шифруется (если не используется StartTLS). Может быть перехвачен.
- **636 (TCP):** LDAPS (LDAP over SSL/TLS). Шифрованное соединение.
- **3268 / 3269:** Global Catalog (глобальный каталог AD). Позволяет искать объекты по всему лесу доменов. 3269 — для LDAPS.

### 3.2. Структура LDAP-каталога (Дерево)
Каталог — это иерархия (дерево). Каждый объект имеет уникальное **DN (Distinguished Name)** — полный путь.
- **Root (Корень):** `dc=company,dc=local`
- **Организационные единицы (OU):** `ou=IT`, `ou=Sales` (отделы).
- **Пользователи/Группы:** `cn=Ivanov, ou=IT, dc=company, dc=local` (CN — Common Name).

### 3.3. Active Directory: Компоненты
- **Домен:** Логическая группа объектов (пользователи, ПК). Основная единица администрирования.
- **Контроллер домена (DC):** Сервер с ролью AD DS. Хранит базу, аутентифицирует, контролирует доступ.
- **Дерево доменов:** Иерархия доменов (родительский и дочерние).
- **Лес (Forest):** Совокупность деревьев, связанных доверительными отношениями. Высший уровень изоляции в AD.

### 3.4. Аутентификация в AD
AD использует два основных протокола:
- **Kerberos:** Современный стандарт. Выдаёт тикеты (TGT, TGS). Сложнее перехватить.
- **NTLM:** Устаревший. Используется для обратной совместимости. Уязвим к **Pass-the-Hash** (передача хеша пароля без знания самого пароля).

## 4. Пример / команда

**Запрос к LDAP (Linux, `ldapsearch`):**
```bash
# Поиск пользователя по имени в домене company.local
ldapsearch -x -H ldap://dc01.company.local -b "dc=company,dc=local" "(cn=Ivanov)"
```

**Проверка LDAP-порта (Nmap):**
```bash
nmap -p 389,636,3268,3269 -sV dc01.company.local
```

**PowerShell (AD):** Найти всех пользователей с включенным SPN (потенциальные цели Kerberoasting):
```powershell
Get-ADUser -Filter {ServicePrincipalName -ne "$null"} -Properties ServicePrincipalName
```

## 5. Для ИБ

LDAP и AD — это «святая святых» корпоративной сети. Их компрометация означает полный контроль над доменом.

| Риск / Атака | Описание | Защита |
|------|--------|--------|
| **LDAP Injection** | Внедрение спецсимволов (`*`, `)`, `&`) в поле логина для обхода аутентификации или извлечения данных. | Валидация и санитизация ввода на стороне сервера. WAF с правилами для LDAP. |
| **Kerberoasting** | Любой доменный пользователь запрашивает TGS-тикет для сервисной учетки (SPN). Тикет шифруется хешем пароля этой учетки и уносится для офлайн-взлома. | Длинные и сложные пароли для сервисных учеток (не человекопонятные). Использование Group Managed Service Accounts (gMSA). Мониторинг Event ID 4769 (запрос TGS с типом шифрования RC4). |
| **DCSync** | Атакующий с правами репликации (полученными через Kerberoasting или Pass-the-Hash) выдает себя за контроллер домена и выкачивает хеши всех паролей (включая KRBTGT). | Ограничить права `Replicating Directory Changes All` только для контроллеров домена. Мониторинг Event ID 4662 (доступ к объектам каталога) с этим правом. |
| **Pass-the-Hash (PtH)** | Использование перехваченного NTLM-хеша пароля для аутентификации без знания самого пароля. | Отключить NTLM, где возможно. Включить Credential Guard. Использовать LAPS (Local Administrator Password Solution). |
| **Golden Ticket** | После кражи хеша KRBTGT атакующий подделывает Kerberos-тикеты (TGT) с произвольными правами и сроком жизни (до 10 лет). | Регулярная (дважды) смена пароля KRBTGT. Мониторинг аномально долгих тикетов. |
