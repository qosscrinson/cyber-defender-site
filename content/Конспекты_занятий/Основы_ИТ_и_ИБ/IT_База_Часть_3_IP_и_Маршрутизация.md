# IT-база. Часть 3: IP-адресация, Маски подсети и Маршрутизация

> [!abstract] Кратко
> Логическая адресация L3. IPv4, публичные и частные адреса, принципы работы масок подсети (CIDR), шлюз по умолчанию, статическая маршрутизация и NAT.

## 1. Зачем нужно
IP-адреса — это логика глобальной сети. Без понимания масок ты не сможешь понять, почему один комп видит другой, а второй — нет. А без NAT не поймешь, как частные адреса выходят в интернет.

## 2. Простыми словами
IP-адрес — это как номер дома. Маска подсети — это индекс: она говорит, какие дома находятся на этой же улице (в одной сети). Шлюз (роутер) — это выезд с улицы на трассу в другой город. NAT — это когда весь многоквартирный дом выходит в интернет через один общий почтовый ящик (один публичный IP).

## 3. Технические детали

### 3.1. IP-адрес
- Логический адрес L3. IPv4 — 32 бита (4 октета), например `192.168.1.10`.
- Состоит из **адреса сети** и **адреса узла (хоста)**.

### 3.2. Публичные и частные IP
- **Публичные:** Уникальны в мире, маршрутизируются в интернете.
- **Частные (серые):** Используются внутри LAN, не маршрутизируются в интернете:
  - `10.0.0.0 – 10.255.255.255` (/8)
  - `172.16.0.0 – 172.31.255.255` (/12)
  - `192.168.0.0 – 192.168.255.255` (/16)

### 3.3. Маска подсети
- Битовая маска: сплошные единицы (1) = адрес сети, нули (0) = адрес хоста.
- Пример: `255.255.255.0` (или `/24`) = 24 единицы, 8 нулей.
- **Количество хостов:** `2^(32 - маска) - 2` (вычитаем адрес сети и broadcast).
- **Пример /28:**

Всего адресов в подсети определяется по формуле: $2^{(32 - \text{маска})}$.

Для `/28`: $32 - 28 = 4$ бита отводится на хосты.

Эти 4 бита могут принимать $2^4 = 16$ различных комбинаций — в подсети `/28` всего **16 IP-адресов**.

Пример для `192.168.1.0/28`:

- адрес сети: `192.168.1.0`
- доступные хосты: `192.168.1.1 — 192.168.1.14`
- broadcast: `192.168.1.15`

Итого: **16 всего = 1 адрес сети + 14 хостов + 1 broadcast.**

Также это видно по маске `/28` = `255.255.255.240`. Размер блока в последнем октете: $256 - 240 = 16$. Поэтому подсети `/28` идут шагом 16: `.0`, `.16`, `.32`, `.48` и т.д.

### 3.4. Шлюз по умолчанию (Default Gateway)
- Адрес роутера. Если получатель не в твоей подсети, пакет отправляется на шлюз.

### 3.5. Маршрутизация
- Процесс выбора пути для пакета.
- **Статическая маршрутизация:** Админ вручную прописывает маршруты (`ip route ...`).
- **Таблица маршрутизации:** База данных на роутере (что куда отправлять).
  - `C` — connected (напрямую).
  - `S` — static (прописан вручную).

### 3.6. NAT (Network Address Translation)
- Трансляция сетевых адресов.
- Позволяет частным IP выходить в интернет через один публичный.
- **SNAT:** Маскирует внутренние IP под внешний (для выхода наружу).
- **DNAT:** Перенаправляет запросы извне на конкретное внутреннее устройство (проброс портов).

### 3.7. Proxy и VPN
- **Proxy:** Посредник на L7. Меняет IP для одного приложения (браузера). Провайдер видит, что трафик идет на прокси.
- **VPN:** Туннель (L3). Заворачивает весь трафик. Шифрует данные. Скрывает содержимое от провайдера.

## 4. Пример / команда

```bash
# Windows: проверка IP
ipconfig /all

# Linux: проверка маршрутов
ip route

# Cisco: таблица маршрутизации
show ip route
```

## 5. Для ИБ

| Риск | Защита |
|------|--------|
| Сканирование сети извне | NAT (скрывает внутренние IP), Firewall |
| Перехват трафика в публичной сети | VPN (шифрование) |
| Подмена шлюза (MITM) | Статические ARP, VPN, HTTPS |
| Использование фейкового прокси | Контроль настроек браузера, запрет на сторонние расширения |
