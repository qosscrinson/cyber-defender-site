# IT-база. Часть 4: Базовые служебные протоколы (ARP, DHCP, DNS, ICMP)

> [!abstract] Кратко
> Фундамент работы сети: как устройства находят MAC по IP (ARP), как получают адреса автоматически (DHCP), как имена превращаются в IP (DNS) и как проверяется связь (ICMP).

## 1. Зачем нужно
Если ты видишь в логах странный IP или понимаешь, что компьютер не получает адрес — ты должен знать, какой протокол за это отвечает и как его диагностировать. Это рабочая рутина L1 SOC.

## 2. Простыми словами
ARP — это крик «Эй, у кого IP 192.168.1.4? Скажи мне свой MAC!». DHCP — это автоматический раздатчик адресов (чтобы не прописывать IP вручную). DNS — это телефонная книга интернета (имя google.com -> IP 142.250...). ICMP — это пинги, проверка «жив ли хост».

## 3. Технические детали

### 3.1. ARP (Address Resolution Protocol)
- Связывает L3 (IP) и L2 (MAC).
- **Как работает:**
  1. Хост PC0 (IP 192.168.1.1) хочет пинговать PC3 (192.168.1.4).
  2. PC0 смотрит ARP-таблицу. Если пусто — отправляет **ARP-запрос (Broadcast):** «У кого IP 192.168.1.4? Скажите свой MAC».
  3. PC3 отвечает **ARP-ответом (Unicast):** «Это я, мой MAC 0004.9A44.0C87».
  4. PC0 записывает в ARP-таблицу IP и MAC.
- **Уязвимость:** ARP-спуфинг (злоумышленник шлет ложные ARP-ответы и перехватывает трафик, выдавая себя за шлюз).

### 3.2. DHCP (Dynamic Host Configuration Protocol)
- Автоматическая выдача IP, маски, шлюза, DNS.
- **Порядок работы (DORA):**
  1. **Discover:** Клиент кричит (broadcast) «Есть тут DHCP?».
  2. **Offer:** Сервер предлагает IP.
  3. **Request:** Клиент просит этот IP.
  4. **Acknowledgment:** Сервер подтверждает.
- *Где DHCP не подходит:* Серверы, принтеры, сетевое оборудование (там нужен статический IP, чтобы адрес не сменился).

### 3.3. DNS (Domain Name System)
- Иерархическая система преобразования имен в IP.
- **Типы записей:**
  - `A` — IPv4.
  - `AAAA` — IPv6.
  - `MX` — почтовые сервера.
  - `CNAME` — псевдоним.
  - `TXT` — текст (часто для защиты от спама).
- **Инструменты:** `nslookup` (Windows/Linux) и `dig` (Linux). Запрос идет: локальный кэш -> DNS-провайдер -> корневой -> TLD -> авторитетный сервер.

### 3.4. ICMP (Internet Control Message Protocol)
- Служебный протокол уведомления об ошибках.
- На нем работают:
  - `ping` — проверка доступности (Эхо-запрос / Эхо-ответ).
  - `tracert` / `traceroute` — определение маршрута (использует TTL).

## 4. Пример / команда

```bash
# Очистить кэш DNS (Windows)
ipconfig /flushdns

# Проверить DNS-запись
nslookup ya.ru 8.8.8.8
dig ya.ru

# Показать ARP-таблицу
arp -a
```

## 5. Для ИБ

| Риск | Защита |
|------|--------|
| ARP-спуфинг (перехват) | DAI (Dynamic ARP Inspection), статические ARP |
| DHCP-спуфинг (злой DHCP-сервер) | DHCP Snooping |
| Отравление DNS-кэша (DNS Spoofing) | DNSSEC, DoH/DoT (шифрование DNS) |
| ICMP Flood (DDoS) | Ограничение ICMP на файрволе, AntiDDoS |
