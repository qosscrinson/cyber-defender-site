# IT-база. Часть 5: Прикладные протоколы и Сетевые порты

> [!abstract] Кратко
> Протоколы, с которыми сталкивается L1 SOC ежедневно: HTTP/HTTPS, RDP, SMTP, SSH. Понятие порта и логика маршрутизации трафика внутри ОС по номерам портов.

## 1. Зачем нужно
Инциденты чаще всего происходят на прикладном уровне (L7). Взлом через RDP, фишинг через SMTP, атака на сайт через HTTP. Знание портов и протоколов — это база для чтения логов SIEM.

## 2. Простыми словами
IP-адрес ведет к компьютеру, а порт — к конкретной программе на нем. HTTP — это как открытка (все видят), HTTPS — как запечатанное письмо (шифрование). RDP — это удаленный рабочий стол (злоумышленники очень любят его брутфорсить). SMTP — почтальон, который только отправляет письма.

## 3. Технические детали

### 3.1. Порты (Ports)
- Числовые идентификаторы (0-65535) для приложений.
- **Well-known (0-1023):** Зарезервированы за службами.
- **Динамические:** Выбираются ОС для исходящих соединений (например, 52140).

### 3.2. HTTP/HTTPS (Порт 80 / 443)
- **HTTP:** Без шифрования. Все данные видны в трафике (пароли, карты).
- **HTTPS:** HTTP + TLS (шифрование). Защищает от прослушивания (MITM).
- **Методы:** `GET` (получить), `POST` (отправить), `PUT` (заменить), `DELETE` (удалить).
- **Коды ответов:**
  - `2xx` — Успех.
  - `3xx` — Перенаправление.
  - `4xx` — Ошибка клиента (например, 404 — не найдено, 403 — доступ запрещен).
  - `5xx` — Ошибка сервера.

### 3.3. RDP (Remote Desktop Protocol, Порт 3389)
- Удаленное управление Windows.
- Шифрует соединение, но уязвим к брутфорсу (подбору паролей).
- *Защита:* Смена порта, MFA, VPN, ограничение по IP.

### 3.4. SMTP (Simple Mail Transfer Protocol, Порт 25/587)
- Только для **отправки** почты.
- Для чтения используются IMAP/POP3.
- Текстовый протокол (команды как в чате).
- *Анализ заголовков:* Поля `Return-Path` и `Reply-To` могут отличаться от реального отправителя (часто используется фишерами).

### 3.5. SSH (Порт 22)
- Secure Shell. Безопасное удаленное управление Linux/Unix.
- Использует пары ключей (публичный/приватный).

### 3.6. NTP (Порт 123 UDP)
- Синхронизация времени. Критично для безопасности (если время сбито, логи не совпадут, и сертификаты не будут работать).

## 5. Для ИБ

| Риск | Защита |
|------|--------|
| Прослушивание трафика HTTP | Переход на HTTPS (TLS), HSTS |
| Brute-force RDP | MFA, ограничение попыток входа, смена порта, VPN |
| Фишинг (Email Spoofing) | SPF, DKIM, DMARC, анализ заголовков `Return-Path` |
| Несанкционированный SSH-доступ | Ключи вместо паролей, fail2ban, смена порта |
