# Fat_Trees

> [!abstract] Кратко
> Перевёрнутое дерево с «толстыми» стволами: удвоение пропускной способности на каждом уровне. Минимальная задержка за счёт параллельных путей. Дорого, сложно масштабировать. Где: суперкомпьютеры, HPC, кластеры ML.

## 1. Зачем нужно
Понять альтернативу Clos для задач, где важнее задержка, чем экономия.

## 2. Простыми словами
Дерево вверх ногами: чем выше, тем толще ветки. Пакет идёт по кратчайшему пути, без «узких мест».

## 3. Технические детали

- **Структура:** перевёрнутое дерево с «толстыми» стволами.
- **Принцип:** удвоение пропускной способности (или числа связей) на каждом уровне.
- **Задержка:** минимальная за счёт множества параллельных путей.

| ✅ Преимущества | ❌ Недостатки |
|---|---|
| Нет «узких мест» | Высокая стоимость |
| Идеально для HPC | Сложное масштабирование (перестройка) |

- **Где:** суперкомпьютеры (Summit), кластеры ML.
- **Clos vs Fat-Trees:** Clos — экономия и гибкость, Fat-Trees — максимальная производительность.

## 4. Пример / команда
Проверка топологии (косвенно):

```bash
show ip route
traceroute <целевой_хост>   # минимум хопов, параллельные пути
```

## 5. Для ИБ

| Риск | Защита |
|------|--------|
| Дорогая инфраструктура → экономия на защите | Планирование бюджета безопасности |
| Параллельные пути → сложный контроль | ACL, микросегментация |
| Нет сегментации → боковое перемещение | VRF, изоляция кластеров |
| Сложное масштабирование → ошибки | Документация, тесты |
