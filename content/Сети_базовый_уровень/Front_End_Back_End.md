# Front_End_Back_End

> [!abstract] Кратко
> Разделение сервисов: Front-End — интерфейс для пользователей (веб, приложение), Back-End — логика, БД, аутентификация. Back-End недоступен извне. Максимальная безопасность, но дорого и сложно синхронизировать.

## 1. Зачем нужно
Понять следующий шаг после DMZ — разделение сервиса на публичную и закрытую части.

## 2. Простыми словами
Витрина магазина (Front-End) и склад с сейфом (Back-End). С улицы видно только витрину.

## 3. Технические детали

| Часть | Роль | Пример |
|---|---|---|
| **Front-End** | Интерфейс для пользователей | Веб-страница магазина |
| **Back-End** | Логика, хранение, обработка | Сервер проверки пароля, БД |

- **Front-End:** обрабатывает запросы, отображает данные, не хранит их.
- **Back-End:** работает с БД, аутентификацией, API, недоступен извне.

| ✅ Плюсы | ❌ Минусы |
|---|---|
| Максимальная безопасность | Высокие затраты |
| Масштабируемость по частям | Сложная синхронизация |

## 4. Пример / команда
Проверка разделения:

```bash
curl -I https://shop.example.com     # front-end
# back-end доступен только из внутренней сети
```

## 5. Для ИБ

| Риск | Защита |
|------|--------|
| Back-End доступен извне | Только внутренняя сеть, firewall |
| Нет аутентификации между Front и Back | mTLS, API-ключи |
| Утечка данных через Front | Валидация, WAF |
| Синхронизация без шифрования | TLS между компонентами |
