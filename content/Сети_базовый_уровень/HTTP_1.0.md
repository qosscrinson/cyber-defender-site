# HTTP 1.0

> [!abstract] Кратко
> Версия 1996 года (RFC 1945). Добавлены заголовки, методы POST и HEAD, коды статуса, поддержка любых типов данных через Content-Type. Главное ограничение: новое TCP-соединение на каждый запрос — медленно.

## 1. Зачем нужно
Понять, какие проблемы HTTP 0.9 закрыл 1.0 и какую проблему оставил.

## 2. Простыми словами
1.0 — это «взрослый» протокол: заголовки, статусы, разные типы файлов. Но по-прежнему на каждый запрос — новое соединение. Каждый запрос — как новый звонок с приветствием.

## 3. Технические детали

**Добавлено относительно 0.9:**
- **Заголовки запроса и ответа** (User-Agent, Content-Type и др.).
- **Методы:** `GET`, `POST`, `HEAD`.
- **Коды статуса:** 200, 404 и др.
- **Типы данных:** любой формат через `Content-Type` (MIME).

**Формат запроса:**
```text
GET /page.html HTTP/1.0
Host: example.com
User-Agent: Mozilla/1.0

```

**Формат ответа:**
```text
HTTP/1.0 200 OK
Content-Type: text/html
Content-Length: 1354

<html>...
```

**Главный минус — новое соединение на каждый запрос:**
- Каждая пара «запрос—ответ» = новое TCP-соединение (рукопожатие + разрыв).
- Страница с 10 картинками = 11 соединений.
- Задержки и нагрузка.

## 4. Пример / команда
Ручной запрос (некоторые серверы ещё понимают 1.0):

```bash
telnet example.com 80
GET / HTTP/1.0
Host: example.com

```

## 5. Для ИБ

| Риск | Защита |
|------|--------|
| Множество соединений → легко устроить DDoS | Ограничение числа соединений с IP |
| Нет заголовка Host → один IP на все сайты | HTTP 1.1 (виртуальный хостинг) |
| Аутентификации нет | Basic-аутентификация появилась позже, в 1.1 — дайджест |
