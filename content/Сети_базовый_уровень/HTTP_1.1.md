# HTTP 1.1

> [!abstract] Кратко
> Версия 1997–1999 (RFC 2068/2616/7230). Главное — постоянное соединение (Keep-Alive), повторное использование TCP для многих запросов. Плюс: Host, кэширование, chunked transfer, дайджест-аутентификация, конвейеризация (pipelining, в итоге отброшена).

## 1. Зачем нужно
Понять, как 1.1 решил главную проблему 1.0 — новое соединение на каждый запрос, и почему это решило проблему не полностью.

## 2. Простыми словами
1.1 — это «один звонок — много заказов». Соединение держится открытым, запросы идут друг за другом без новых рукопожатий.

## 3. Технические детали

**Keep-Alive:**
- `Connection: keep-alive` — соединение не закрывается после ответа.
- Один TCP-сеанс на много запросов.
- Меньше рукопожатий → меньше задержек.

**Host:**
```text
GET / HTTP/1.1
Host: example.com

```
- Один IP — много сайтов (виртуальный хостинг).

**Кэширование:**
- `Cache-Control`, `ETag`, `If-Modified-Since` — контролируют актуальность кеша.

**Chunked Transfer:**
- Ответ может отправляться кусками, не зная размер заранее (`Transfer-Encoding: chunked`).

**Дайджест-аутентификация:**
- Пароль не передаётся открытым текстом (в отличие от Basic).

**Pipelining и его смерть:**
- Идея: несколько запросов подряд без ожидания ответов.
- Проблема: ответы приходят строго по порядку (head-of-line blocking). Медленный запрос блокирует всё позади.
- В итоге отброшен — полностью решён только в HTTP/2.

## 4. Пример / команда

```bash
curl -H "Connection: keep-alive" http://example.com/
```

## 5. Для ИБ

| Риск | Защита |
|------|--------|
| Keep-Alive держит соединения открытыми → исчерпание ресурсов | Таймауты idle-соединений |
| Slowloris (медленные запросы держат соединение) | Rate limiting, WAF |
| Кэш-отравление через Cache-Control | Правильная настройка директив кэша |
| Basic-аутентификация без TLS | Всегда HTTPS |
