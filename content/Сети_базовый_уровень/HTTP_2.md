# HTTP 2

> [!abstract] Кратко
> Версия 2015 (RFC 7540). Главное — мультиплексирование: много запросов в одном соединении без блокировки. Бинарный протокол вместо текстового, сжатие заголовков HPACK, приоритеты потоков, server push. На практике только поверх TLS.

## 1. Зачем нужно
Понять, как HTTP/2 убил head-of-line blocking из 1.1 и почему сайты стали загружаться заметно быстрее без смены TCP.

## 2. Простыми словами
1.1 — это очередь в кассу: один медленный покупатель блокирует всех. HTTP/2 — это супермаркет с одной широкой лентой, где заказы едут параллельно и не мешают друг другу.

## 3. Технические детали

**Мультиплексирование:**
- Соединение делится на **потоки (streams)**.
- Каждый поток — отдельный запрос-ответ.
- Потоки идут вперемешку, не ждут друг друга → head-of-line blocking на уровне HTTP устранён.
- TCP-соединение одно → меньше рукопожатий и TLS-сессий.

**Бинарный формат:**
- В отличие от текстовых 1.0/1.1 — бинарные фреймы.
- Эффективнее парсить, меньше ошибок разбора.

**HPACK:**
- Сжатие заголовков: повторяющиеся заголовки (User-Agent, Accept) передаются ссылками на предыдущие.

**Приоритеты:**
- Клиент указывает важность потоков (например, CSS важнее картинок).

**Server Push:**
- Сервер может отправить ресурсы, которые клиент ещё не запросил (например, стили к уже запрошенной странице).

**Транспорт:**
- Спецификация допускает и TCP, но на практике — почти всегда TLS (браузеры поддерживают h2 только по HTTPS).

## 4. Пример / команда
Проверка, что сайт поддерживает HTTP/2:

```bash
curl -I --http2 https://example.com
```

## 5. Для ИБ

| Риск | Защита |
|------|--------|
| TCP-level head-of-line blocking никуда не делся | HTTP/3 (QUIC) |
| Усложнение сниффинга для защиты | NTI/NGFW с поддержкой h2 |
| Незакрытые потоки → исчерпание ресурсов | Лимиты потоков на сервере |
| Server push → ненужный трафик | Отключить push, использовать preload |
