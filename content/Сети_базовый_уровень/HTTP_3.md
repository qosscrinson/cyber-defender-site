# HTTP 3

> [!abstract] Кратко
> Версия 2022 (RFC 9114). Транспорт — не TCP, а QUIC поверх UDP. Шифрование встроено в протокол (TLS 1.3), меньше задержек при установке соединения, решение проблемы TCP head-of-line blocking на транспортном уровне.

## 1. Зачем нужно
Понять, как HTTP/3 убрал оставшиеся узкие места TCP и зачем он QUIC.

## 2. Простыми словами
HTTP/3 — это «смена фундамента». TCP ограничен (рукопожатия, блокировки, адресация). QUIC — новый транспорт поверх UDP: гибкий, шифрованный, быстрый.

## 3. Технические детали

**QUIC (Quick UDP Internet Connections):**
- Транспорт на базе UDP (порт 443 по умолчанию).
- Шифрование TLS 1.3 встроено в протокол (не отдельный слой).
- Меньше задержек: соединение устанавливается за 1 RTT (а с 0-RTT — почти мгновенно для известных серверов).

**Почему не TCP:**
- TCP в ядре ОС — трудно менять.
- UDP — «песочница»: можно реализовать всё в userspace.
- QUIC сам обеспечивает надёжность и порядок там, где нужно.

**Мультиплексирование без блокировки:**
- Потоки независимы на уровне протокола, потеря пакета в одном потоке не блокирует остальные (в отличие от TCP h2).

**Миграция соединения:**
- Идентификатор соединения (Connection ID) вместо 4-tuple.
- Смена Wi-Fi → мобильный интернет: соединение не рвётся.

## 4. Пример / команда
Проверка поддержки HTTP/3:

```bash
curl --http3 https://cloudflare-quic.com
```

## 5. Для ИБ

| Риск | Защита |
|------|--------|
| QUIC сложнее инспектировать (всё шифровано) | Инструменты с поддержкой QUIC (Zeek, Suricata) |
| Туннелирование через QUIC | Ограничение UDP 443 на выходе |
| Новые уязвимости протокола | Обновления, мониторинг CVE |
| Смена IP при миграции → затрудняет трекинг | Логи Connection ID |
