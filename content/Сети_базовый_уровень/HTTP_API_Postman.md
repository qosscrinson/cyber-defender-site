# HTTP_API_Postman

> [!abstract] Кратко
> Инструмент для работы с HTTP API: конструктор запросов, коллекции, окружения, тесты. В ИБ — разведка API, поиск ошибок авторизации (IDOR, Broken Access Control).

## 1. Зачем нужно
API — главный канал обмена данными в современных сервисах. Тестировать запросы через Postman быстрее и точнее, чем через браузер: видно заголовки, статусы, тело ответа.

## 2. Простыми словами
Postman — это «пульт управления» для API. Вместо кликанья по сайту ты прямо посылаешь серверу запросы и смотришь, что он отвечает. Полезно и разработчику, и тому, кто ищет уязвимости.

## 3. Технические детали

**Основные функции:**
- **Конструктор запросов:** метод, URL, заголовки, тело (JSON, form-data).
- **Коллекции:** набор запросов, которые можно выполнять последовательно.
- **Окружения (environments):** переменные (`{{base_url}}`, `{{token}}`).
- **Тесты:** скрипты на JS для проверки ответа.
- **История:** все запросы с ответами.

**Пример запроса:**

| Параметр | Значение |
|---|---|
| Метод | GET |
| URL | `https://api.example.com/users/123` |
| Заголовок | `Authorization: Bearer {{token}}` |

**Что смотреть в ответе:**

| Поле | Зачем |
|---|---|
| Статус | 200/401/403/404 — если 200 без прав, это IDOR |
| Заголовки | CORS, Content-Type, security headers |
| Тело | Утечка полей (email, роль, ID других) |

## 4. Пример / команда
Проверка API без Postman (curl):

```bash
curl -H "Authorization: Bearer TOKEN" https://api.example.com/users/123
```

## 5. Для ИБ

| Риск | Защита |
|------|--------|
| IDOR (перебор ID в URL) | Проверка прав на каждый объект |
| Утечка данных в ответе API | Минимизация полей в ответе |
| Нет аутентификации на эндпоинте | Обязательно проверять все эндпоинты |
| Заголовки CORS `*` | Явные домены вместо wildcard |
