# HTTP_кэширование

> [!abstract] Кэширование HTTP
> Механизм сохранения копий ответов для повторного использования. Заголовки: Cache-Control, ETag, If-None-Match, Expires. Виды кешей: браузер, прокси, CDN. Ускоряет загрузку и снижает нагрузку на сервер.

## 1. Зачем нужно
Понять, как браузеры и серверы экономят трафик и время, и какие ошибки настройки кеша приводят к показу чужих данных.

## 2. Простыми словами
Кэш — это «заметки на память». Ты уже скачивал страницу — браузер сохранил копию. Второй раз — показывает копию, не обращаясь к серверу.

## 3. Технические детали

**Ключевые заголовки:**

| Заголовок | Что делает |
|---|---|
| `Cache-Control: max-age=3600` | Хранить 1 час |
| `Cache-Control: no-cache` | Кэшировать, но проверять актуальность |
| `Cache-Control: no-store` | Не кэшировать вовсе |
| `Cache-Control: private` | Только в браузере, не в общих кешах |
| `ETag` | Уникальный маркер версии ресурса |
| `If-None-Match` | Клиент спрашивает: «у тебя ещё эта версия?» — сервер отвечает 304 |
| `Expires` | Устаревший аналог max-age |

**Проверка актуальности (conditional request):**
1. Клиент хранит ETag от прошлого ответа.
2. Запрос с `If-None-Match: <etag>`.
3. Сервер отвечает `304 Not Modified` — тело не отправляется.

**Виды кешей:**
- **Браузерный** — на устройстве.
- **Прокси-кеш** — на корпоративном прокси.
- **CDN-кеш** — на edge-узлах (см. [[CDN_как_Overlay]]).

## 4. Пример / команда
Проверка заголовков кеша:

```bash
curl -I https://example.com
```

## 5. Для ИБ

| Риск | Защита |
|------|--------|
| Кэширование чувствительных данных в общих кешах | `Cache-Control: private, no-store` |
| Отравление кеша (cache poisoning) | Проверка ключей кеша, ограничение вариаций |
| Устаревший кеш → показ неактуальных данных | Правильные max-age, ETag |
| Кэш персональных данных в браузере на чужом ПК | no-store на приватных страницах |
