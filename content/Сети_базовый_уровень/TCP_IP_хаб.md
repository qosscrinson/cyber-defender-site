# TCP/IP — хаб-заметка (словарь и ресурсы)

> [!abstract] Кратко
> Единая точка входа для изучения стека TCP/IP. Содержит базовый словарь терминов (L2-L4), краткий пересказ принципов работы, технические детали инкапсуляции и подборку лучших ресурсов для визуализации и практики.

## 1. Зачем нужно
Стек TCP/IP — фундамент интернета. В этой заметке собраны все базовые определения (от MAC-адреса до 3-way handshake), чтобы не искать их по разным источникам. Она служит навигатором (хабом) по остальным атомарным заметкам и дает практические инструменты для закрепления теории.

## 2. Простыми словами
Это «словарь и карта». Если ты забыл, чем отличается IP-пакет от IP-датаграммы или как расшифровывается CIDR — ты открываешь эту заметку. А в конце тебя ждут интерактивные игры и симуляторы, чтобы увидеть, как пакеты летают по сети своими глазами.

## 3. Технические детали

### 3.1. Словарь базовых терминов

> [!example] Компьютерная сеть
> - **Просто:** Группа устройств, которые соединены между собой и могут обмениваться данными. Как класс, где все ученики передают друг другу записки.
> - **Технически:** Множество вычислительных узлов (hosts), связанных линиями связи (links) и совместно использующих ресурсы посредством стандартизированных протоколов.

> [!example] Хост (Host)
> - **Просто:** Любое устройство в сети — компьютер, телефон, сервер, даже умная лампочка.
> - **Технически:** Устройство, участвующее в обмене данными на уровне IP, имеющее как минимум один сетевой интерфейс с IP-адресом.

> [!example] PDU (Protocol Data Unit)
> - **Просто:** «Посылка» с данными, состоящая из заголовка и полезной части.
> - **Технически:** Блок данных протокола: заголовок (header) + полезная нагрузка (payload). На разных уровнях носит разные названия: фрейм, пакет, сегмент, датаграмма.

> [!example] Инкапсуляция
> - **Просто:** Упаковка данных одного протокола внутрь другого. Как вложить письмо в конверт, а конверт — в посылку.
> - **Технически:** Вложение PDU вышестоящего уровня в payload PDU нижестоящего (например, TCP-сегмента в IP-пакет, а IP-пакета — в Ethernet-фрейм).

> [!example] Порт
> - **Просто:** «Номер квартиры» внутри компьютера. Чтобы данные попали не просто к устройству, а в нужную программу.
> - **Технически:** 16-битный идентификатор процесса (L4), позволяющий одному IP-адресу поддерживать множество одновременных соединений.

### 3.2. Адресация и модели
*   **MAC-адрес:** 48-битный физический адрес интерфейса L2 (например, `A4:5E:60:12:34:56`). Присваивается на заводе.
*   **IP-адрес:** 32-битный (IPv4) или 128-битный (IPv6) логический адрес L3.
*   **Маска подсети / CIDR:** Показывает, какая часть IP-адреса относится к сети, а какая — к хосту. `192.168.0.0/24` — первые 24 бита это сеть.
*   **Unicast / Broadcast / Multicast:** Письмо одному / крик всем / крик группе.
*   **NAT:** «Швейцар» — подменяет внутренние частные IP-адреса на один внешний публичный.
*   **Модель OSI:** 7 уровней (эталон).
*   **Модель TCP/IP:** 4 уровня (рабочая): Канальный (L1-L2), Межсетевой (L3), Транспортный (L4), Прикладной (L5-L7).

### 3.3. Сетевой уровень (L3)
*   **IP:** Обеспечивает негарантированную доставку датаграмм.
*   **IP-датаграмма vs IP-пакет:** Датаграмма — то, что приходит с L4. Пакет — то, что передается в сети (ограничен MTU). Если датаграмма больше MTU, включается **фрагментация**.
*   **MTU:** Максимальный размер посылки (обычно 1500 байт).
*   **ARP:** Определяет MAC-адрес по известному IP в локальном сегменте.
*   **ICMP:** Служебные сообщения (например, пинг — «ты тут?»).

### 3.4. Транспортный уровень (L4)
*   **UDP:** Быстрая доставка без гарантий. Без установки соединения.
*   **TCP:** Надежная доставка с проверкой. Устанавливает соединение через **3-way handshake** (SYN → SYN/ACK → ACK). Использует Sequence Number (порядок) и Acknowledge Number (подтверждение), флаги (SYN, ACK, FIN, RST), окно приема (Window Size).
*   **MSS:** Максимальный кусок данных внутри одного TCP-сегмента (MTU минус заголовки, обычно 1460 байт).

### 3.5. Прикладной уровень (L7)
*   **DHCP:** Автонастройка (цикл DORA: Discover → Offer → Request → Ack).
*   **DNS:** Распределенная база доменных имен. Превращает `habr.com` в IP.
*   **Резолвер:** Локальный компонент ОС, кеширующий ответы DNS.

## 5. Для ИБ

| Риск | Защита |
| :--- | :--- |
| **ARP-спуфинг** (подмена MAC) | Dynamic ARP Inspection (DAI), статические ARP |
| **IP-спуфинг** (подмена IP) | uRPF (фильтрация на маршрутизаторах), Ingress/Egress filtering |
| **TCP SYN-flood** (переполнение таблицы соединений) | SYN cookies, rate limiting на фаерволе |
| **Перехват сессии TCP** (Session Hijacking) | Шифрование (TLS/IPsec), случайная генерация ISN |
| **DNS-спуфинг** (подмена ответов) | DNSSEC, DoH/DoT |
| **DHCP-спуфинг** (выдача ложного шлюза) | DHCP Snooping на коммутаторах |
