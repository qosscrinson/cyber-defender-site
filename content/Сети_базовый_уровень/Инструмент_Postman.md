# Инструмент Postman

> [!abstract] Кратко
> Инструмент для отправки HTTP-запросов, тестирования, отладки и документирования API. Позволяет работать с API без написания кода на Python или JavaScript.

## 1. Зачем нужно
Чтобы проверять работу API, не тратя время на написание кода. Разработчики тестируют эндпоинты, тестировщики проверяют сценарии, ИБ-специалисты исследуют уязвимости. Всё в одном окне: запрос, ответ, сохранение, автоматизация.

## 2. Простыми словами
Это **пульт управления** для API. Ты не лезешь внутрь телевизора с паяльником (не пишешь скрипты), чтобы переключить канал. Ты нажимаешь кнопки: выбираешь метод (GET/POST), вводишь адрес, добавляешь данные, жмёшь "Send" и смотришь результат. Если удачно — сохраняешь кнопку в "Избранное" (коллекцию), чтобы пользоваться снова.

## 3. Технические детали

### 3.1. Основные элементы интерфейса
*   **Workspace (Рабочее пространство):** Папка верхнего уровня для разделения проектов.
*   **Collection (Коллекция):** Набор сохраненных запросов (группировка по темам).
*   **Request (Запрос):** Один HTTP-запрос (метод, URL, заголовки, тело).
*   **Environment (Окружение):** Набор переменных (например, Dev, Prod).
*   **Response (Ответ):** Статус-код, заголовки и тело ответа (JSON).

### 3.2. Рабочий процесс (Workflow)
1. **Создать коллекцию** → 2. **Добавить запрос** → 3. **Настроить параметры** (Headers, Body) → 4. **Отправить (Send)** → 5. **Проанализировать ответ** → 6. **Сохранить**.

### 3.3. Переменные и окружения
Хардкодить URL и токены — плохая практика (риск утечки). Используй переменные:
*   **Global:** Везде.
*   **Environment:** В рамках выбранного окружения. Например, `{{base_url}}` = `https://api.dev.local`.
*   **Collection:** В рамках коллекции (`{{token}}`).
*   **Local:** Только для текущего запуска.

**Пример:** Вместо `https://api.example.com/users` пишешь `{{base_url}}/users`. В окружении "Dev" подставится один URL, в "Prod" — другой.

### 3.4. Продвинутые возможности
*   **Pre-request Script (JS):** Выполнить код *до* отправки запроса (например, сгенерировать метку времени).
*   **Tests (JS):** Автотесты *после* получения ответа (проверить статус 200 и наличие поля в JSON).
*   **Collection Runner:** Запуск всей коллекции запросов по очереди.
*   **Newman:** Запуск коллекций Postman из командной строки (для CI/CD).
*   **Mock Server:** Имитация API, если бэкенд еще не готов.

## 4. Пример / команда
**Настройка запроса в Postman:**
*   Метод: `POST`
*   URL: `{{base_url}}/api/v1/users`
*   Headers: `Content-Type: application/json`, `Authorization: Bearer {{token}}`
*   Body (raw JSON): `{"name": "Иван"}`

**Эквивалент в curl (что Postman делает под капотом):**
```bash
curl -X POST "{{base_url}}/api/v1/users" -H "Content-Type: application/json" -H "Authorization: Bearer {{token}}" -d '{"name":"Иван"}'
```
> [!tip] Фишка
> В Postman можно нажать кнопку `Code` (справа) и посмотреть, как этот же запрос выглядит на Python, cURL, JavaScript и других языках.

## 5. Для ИБ

| Риск / Задача | Как использовать Postman | Защита / Мера |
|---|---|---|
| **Поиск BOLA/IDOR** | Менять ID в URL (`/users/1` → `/users/2`) и смотреть, отдаёт ли сервер чужие данные. | Тестировать авторизацию на каждом объекте. |
| **Проверка авторизации** | Подставлять просроченные/битые токены, менять роли в JWT. | Проверять, что 401/403 возвращаются корректно. |
| **Утечка через ошибки** | Отправлять битые запросы, смотреть, не отдаёт ли сервер stack trace. | Единый формат ошибок, логирование на сервере. |
| **Хранение секретов** | Токены и пароли могут сохраниться в истории или экспорте коллекции. | Не коммитить коллекции с реальными токенами в Git; использовать окружения. |
| **Перехват трафика** | Встроенный Proxy в Postman может перехватывать запросы с телефона. | Использовать HTTPS, проверять сертификаты. |

**Главная мысль:** Postman — это легальный инструмент для атакующего. Всё, что делает пентестер через `curl`, он может сделать через Postman быстрее и нагляднее. Твоя задача — использовать его для защиты: находить дыры раньше, чем это сделают другие.
