# Интерфейс сокетов (Socket API)

> [!abstract] Кратко
> Программный интерфейс для общения приложений по сети. Сокет — это «дверь», через которую программа отправляет и принимает данные. В Python реализуется через модуль `socket`.

## 1. Зачем нужно
Приложения не работают с сетевыми пакетами напрямую (это слишком сложно). Сокет берет на себя рутину: установку TCP-соединения, разбивку на пакеты, отправку и сборку.

## 2. Простыми словами
Программа — это жилец в доме. Сокет — это его почтовый ящик. Ты вешаешь на него номер квартиры (порт) и адрес (IP). Дальше либо ждешь письмо (сервер), либо идешь к чужому ящику отправлять (клиент).

## 3. Технические детали
*   `SOCK_STREAM` — TCP (надежно, с порядком).
*   `SOCK_DGRAM` — UDP (быстро, без гарантий).
*   `AF_INET` / `AF_INET6` — семейства адресов (IPv4 / IPv6).

## 4. Пример / команда (TCP-сервер на Python)
```python
import socket

# 1. Создаем сокет (IPv4, TCP)
s = socket.socket(socket.AF_INET, socket.SOCK_STREAM)

# 2. Привязываем к IP и порту
s.bind(('192.168.0.1', 8888))

# 3. Слушаем (очередь до 5)
s.listen(5)

# 4. Принимаем соединение
conn, addr = s.accept()

# 5. Читаем и отправляем обратно
while True:
    data = conn.recv(1024)
    if not data:
        break
    conn.sendall(data)

conn.close()
```

## 5. Для ИБ

| Риск | Что делает атакующий | Защита |
|------|----------------------|--------|
| **Реверс-шелл (Reverse Shell)** | Внедряет скрипт, который сам подключается (`connect()`) к IP атакующего и отдает управление ОС. | EDR, мониторинг исходящих соединений на высокие порты, запрет скриптов. |
| **Бинд-шелл (Bind Shell)** | Запускает сервер (`bind()` + `listen()`) на жертве, атакующий подключается к нему. | Файрволы (запрет входящих), контроль открытых портов. |
| **Исчерпание сокетов** | Открывает тысячи соединений, исчерпывая лимиты ОС. | Лимиты на файловые дескрипторы (`ulimit`), SYN-cookies. |

**Главная мысль:** Сокеты — мощный инструмент. Разработчик делает сервисы, атакующий — бэкдоры. Разница в контексте.
