# Методы_HTTP

> [!abstract] Кратко
> Методы HTTP — «глаголы» запроса: GET, POST, PUT, DELETE, PATCH, HEAD, OPTIONS. Свойства: безопасные (не меняют состояние), идемпотентные (повтор = тот же результат). Коды ответов показывают, как сервер понял запрос.

## 1. Зачем нужно
Понимать методы — основа работы с API и анализа трафика. Для ИБ это ключ к поиску уязвимостей: что запрос должен делать, что он делает на самом деле.

## 2. Простыми словами
GET — «дай посмотреть». POST — «прими новое». PUT — «замени целиком». PATCH — «подправь кусочек». DELETE — «удали». Каждый метод — разное действие, но сервер может их путать — тогда дыра.

## 3. Технические детали

| Метод | Что делает | Тело запроса | Идемпотентен | Безопасен |
|---|---|---|---|---|
| **GET** | Получить ресурс | Нет | Да | Да |
| **POST** | Создать ресурс / отправить данные | Да | Нет | Нет |
| **PUT** | Заменить ресурс целиком | Да | Да | Нет |
| **PATCH** | Частично обновить | Да | Нет* | Нет |
| **DELETE** | Удалить ресурс | Нет | Да | Нет |
| **HEAD** | Как GET, но без тела ответа | Нет | Да | Да |
| **OPTIONS** | Какие методы доступны для URL | Нет | Да | Да |

- **Безопасный метод** — не меняет состояние сервера (GET, HEAD, OPTIONS).
- **Идемпотентный** — повтор запроса даёт тот же результат (PUT, DELETE, GET); POST — нет (создаст новый объект каждый раз).
- **GET vs POST:** GET — параметры в URL (видны в логах, закладках), POST — в теле (не в URL, но не «шифрование»).

**Коды ответов по методам:**

| Метод | Успех | Ошибка клиента |
|---|---|---|
| GET | 200 | 404 (нет), 403 (запрещено) |
| POST | 201 (создано) | 400 (неверное тело), 409 (конфликт) |
| PUT | 200 / 201 | 404, 403 |
| DELETE | 200 / 204 | 404, 403 |

## 4. Пример / команда
Проверить методы для URL:

```bash
curl -I -X OPTIONS https://api.example.com/users
curl -X POST -H "Content-Type: application/json" -d '{"name":"test"}' https://api.example.com/users
```

## 5. Для ИБ

| Риск | Защита |
|------|--------|
| GET с побочными эффектами → CSRF-атака | Только идемпотентные GET, CSRF-токены на POST |
| OPTIONS раскрывает список методов → разведка | Отключить или ограничить OPTIONS |
| TRACE → Cross-Site Tracing (XST), кража cookie | Блокировать TRACE |
| DELETE/PUT без аутентификации | Проверять права на каждый метод и объект |
| POST вместо GET для «обычных» страниц → невидимость в логах | Мониторинг обоих методов |
