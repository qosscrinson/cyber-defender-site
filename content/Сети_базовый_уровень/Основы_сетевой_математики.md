# Основы_сетевой_математики

> [!abstract] Кратко
> Расчёт подсетей: степени двойки, формула `2^n - 2` хостов, соответствие префиксов маскам. Примеры /24, /26, /28. Как делить сеть без ошибок.

## 1. Зачем нужно
Без базовой математики не понять, откуда берутся границы подсетей, сколько хостов в `/26` и почему `/31` — особый случай. Это ежедневный навык сетевика.

## 2. Простыми словами
Маска — это черта: сколько бит «адрес дома», сколько «номер квартиры». Чем больше бит отдано номеру дома — тем меньше квартир в нём.

## 3. Технические детали

**Степени двойки:**

| n | 2^n |
|---|---|
| 4 | 16 |
| 6 | 64 |
| 8 | 256 |
| 10 | 1024 |
| 16 | 65536 |

**Формула хостов:** `2^(32 - префикс) - 2` (вычитаем адрес сети и broadcast).

**Таблица типовых префиксов:**

| Префикс | Маска | Хостов |
|---|---|---|
| /24 | 255.255.255.0 | 254 |
| /25 | 255.255.255.128 | 126 |
| /26 | 255.255.255.192 | 62 |
| /27 | 255.255.255.224 | 30 |
| /28 | 255.255.255.240 | 14 |
| /30 | 255.255.255.252 | 2 (point-to-point) |

- **Мнемоника:** каждый бит маски отнимает ровно половину оставшихся хостов: 254 → 126 → 62 → 30 → 14.

**Пример расчёта /26 для `192.168.1.0/26`:**
- 32 − 26 = 6 бит на хосты → 2^6 = 64 адреса → 62 хоста.
- Блок маски в последнем октете: 256 − 192 = 64.
- Подсети идут шагом 64: `.0–.63`, `.64–.127`, `.128–.191`, `.192–.255`.

**VLSM (Variable Length Subnet Mask):**
- Делить сеть на куски разного размера под разные нужды: маршрутизаторам — /30, офисам — /24, серверам — /27.
- Правило: сначала самые большие подсети, потом меньшие из остатка.

## 4. Пример / команда
Быстрый расчёт подсети (Linux):

```bash
ipcalc 192.168.1.0/26       # если установлен
python3 -c "print(2**(32-26)-2)"   # 62 хоста
```

## 5. Для ИБ

| Риск | Защита |
|------|--------|
| Слишком большая подсеть → больше атакуемых хостов в одном сегменте | Дробить на меньшие подсети, сегментация |
| Ошибка в маске → хосты «не видят» друг друга или видят лишнее | Проверка расчёта, ipcalc, документация |
| /30 на линке не использован → адрес в общий пул | Резервировать /30 (или /31) для p2p |
| Пересекающиеся подсети после VLSM | План адресации, IPAM |
