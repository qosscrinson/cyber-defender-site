# Протокол_ARP

> [!abstract] Кратко
> Протокол канального уровня (L2), предназначенный для определения MAC-адреса устройства по его известному IP-адресу.

## 1. Зачем нужно
Ни одно устройство не начнет передачу данных, пока не узнает MAC-адрес шлюза или следующего узла. ARP автоматически находит этот MAC-адрес, избавляя от ручной настройки таблиц.

## 2. Простыми словами
Это «справочная». У тебя есть имя человека (IP-адрес), но ты не знаешь его физический адрес (MAC). Ты кричишь на всю комнату (broadcast): «Кто такой Вася?». Вася откликается и дает свой MAC-адрес.

## 3. Технические детали
*   **Уровень:** L2 (Канальный).
*   **Режим работы:** Запрос-ответ.
*   **Алгоритм:**
    1. Устройство шлет ARP-запрос на широковещательный MAC (`FF:FF:FF:FF:FF:FF`).
    2. Все устройства в сети получают запрос.
    3. Устройство с совпадающим IP отправляет ARP-ответ со своим MAC.
    4. Отправитель сохраняет MAC в свою ARP-таблицу для будущих запросов.

## 4. Пример / команда
Очистка ARP-таблицы и проверка текущих записей:

```bash
arp -a
arp -d *
```

## 5. Для ИБ

| Риск | Защита |
|------|--------|
| **ARP-спуфинг** (злоумышленник шлет ложные ARP-ответы, чтобы перехватить трафик, выдав свой MAC за MAC шлюза) | Dynamic ARP Inspection (DAI) на коммутаторах, статические ARP-записи для шлюзов |
