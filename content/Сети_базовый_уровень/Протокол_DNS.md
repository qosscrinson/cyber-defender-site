# Протокол_DNS

> [!abstract] Кратко
> Распределенная система (L7), преобразующая доменные имена (habr.com) в IP-адреса (178.248.237.68). Работает как глобальная телефонная книга. Использует UDP (порт 53). Если ответ не влезает в UDP (превышает 512 байт или лимит EDNS0), сервер ставит флаг TC (Truncated), и клиент повторяет запрос по TCP (fallback).

## 1. Зачем нужно
Человеку сложно запоминать числовые IP-адреса. Нам проще запомнить `habr.com`. DNS берет имя и выдает соответствующий номер. Без DNS интернетом пользоваться было бы невозможно.

## 2. Простыми словами
Представь, что ты хочешь позвонить другу. Ты не помнишь его номер, но помнишь имя. Ты открываешь телефонную книгу и находишь номер. **DNS — это телефонная книга интернета.** Она не лежит в одном месте (это распределенная система). Главная книга (Корневой домен) принадлежит ICANN. Она не хранит номера всех сайтов, а знает, где искать зону `.ru`, `.com` и т.д.

## 3. Инфраструктура и иерархия
DNS — это **дерево доменных имен**:
* **Корневой домен** (`.`) — один на весь интернет, управляется ICANN.
* **Зоны первого уровня** (`.com`, `.org`, `.ru`) — управляются регистраторами.
* **Зоны второго уровня** (`yandex.ru`) — регистрируются организациями.
* **Поддомены** (`maps.yandex.ru`).
* **DNS Resolver** — сервер (обычно у провайдера), который принимает запрос от твоего ПК и бегает по этому дереву, чтобы найти нужный IP.

## 4. Технические детали

### Режимы работы DNS
* **Итеративный запрос:** Сервер не знает ответа, но говорит: «Я не знаю, но спроси вот у этого сервера». (Так общаются серверы между собой).
* **Рекурсивный запрос:** Сервер сам бегает по всем серверам, собирает ответ и отдает готовый результат клиенту. (Так работает твой ПК и DNS Resolver).

### Типы ответов
* **Авторитетный (authoritative):** Ответ от сервера, который **обслуживает** эту зону. Данные из файлов на диске. Ему можно доверять.
* **Неавторитетный (non-authoritative):** Ответ из кэша промежуточного сервера. Данные могли устареть (в `nslookup` пишет «Не заслуживающий доверия ответ»).

### Формат пакета и транспорт
* **Уровень:** L7 (Прикладной).
* **Транспорт:** UDP (порт 53) — по умолчанию. TCP (порт 53) — если ответ > 512 байт (зональный трансфер, DNSSEC).
* **Заголовок (12 байт):** ID запроса, флаги, количество запросов/ответов.
* **Тело:** Запросы (Queries), Ответы (Answers), Авторитетные серверы (Authority), Доп. информация (Additional).

### Типы записей
* `A` — домен → IPv4.
* `AAAA` — домен → IPv6.
* `MX` — сервер обработки почты.
* `CNAME` — псевдоним (алиас) другого домена.

## 5. Локальные средства (Файл hosts и утилиты)
Прежде чем идти в DNS, компьютер смотрит в локальный файл `hosts`. Это статическая таблица.
* **Linux/Unix:** `/etc/hosts`
* **Windows:** `C:\Windows\System32\drivers\etc\hosts`

**Утилита `nslookup`** — командная строка для проверки DNS-запросов:
```text
> nslookup habr.com
Сервер:  Unknown
Address:  192.168.1.1
Не заслуживающий доверия ответ:
habr.com
Address:  178.248.237.68
```

## 6. Пример / команда
* Проверить файл hosts: `cat /etc/hosts` (Linux) или `type C:\Windows\System32\drivers\etc\hosts` (Windows).
* Узнать IP сайта: `nslookup example.com` или `dig example.com`.
* Очистить кэш DNS (Windows): `ipconfig /flushdns`.

## 7. Для ИБ

| Риск | Что делает атакующий | Защита |
|------|----------------------|--------|
| **DNS Spoofing / Cache Poisoning** | Подсовывает ложный DNS-ответ (например, через ARP-спуфинг), чтобы жертва шла на IP атакующего (фишинг). | DNSSEC (цифровая подпись зон), DoH/DoT (шифрование запросов). |
| **DNS Tunneling** | Прячет передачу данных (например, вывод украденных файлов) внутри DNS-запросов. Файрволы часто пропускают UDP 53. | Мониторинг аномально длинных TXT-запросов, DPI (Deep Packet Inspection). |
| **DDoS-амплификация** | Использует открытые рекурсивные DNS-серверы для заваливания жертвы трафиком. | Закрыть рекурсию для внешних IP, rate-limiting. |
| **Подмена файла hosts** | Вредоносное ПО прописывает в `hosts` ложные IP для банковских сайтов. | Антивирус, контроль целостности системных файлов, права доступа. |

**Главная мысль:** DNS — это доверие по умолчанию. Если ты не используешь DNSSEC или DoH, ты не можешь быть уверен на 100%, что `habr.com` ведет на настоящий сервер, а не на клон атакующего.
