# Протокол_IGMP

> [!abstract] Кратко
> Протокол сетевого уровня (L3) для управления групповыми соединениями (multicast). Позволяет маршрутизаторам знать, какие устройства хотят получать multicast-трафик.

## 1. Зачем нужно
Для эффективной передачи данных сразу группе получателей (например, видеотрансляции). Без IGMP маршрутизатор не знал бы, куда отправлять поток.

## 2. Простыми словами
Это «подписка на рассылку». Ты говоришь маршрутизатору: «Я хочу получать этот канал». Он записывает тебя в список и начинает передавать данные только тем, кто подписался.

## 3. Технические детали
- **Уровень:** L3 (сетевой).
- **Multicast:** передача одного потока данных сразу группе получателей в разных подсетях.
- **Алгоритм:**
    1. Клиент отправляет IGMP Membership Report (подписывается на группу, например, `224.2.2.4`).
    2. Маршрутизатор регистрирует клиента в таблице.
    3. Маршрутизатор начинает пересылать трафик.
    4. При отключении клиента маршрутизатор опрашивает устройства и обновляет таблицу.
- **Версии:** IGMPv2, IGMPv3 (обратно совместимы).

## 4. Пример / команда
Просмотр multicast-групп на интерфейсе (в Linux):

```bash
ip maddr show
```

## 5. Для ИБ

| Риск | Защита |
|------|--------|
| IGMP-спуфинг (отправка ложных отчётов для перегрузки канала) | IGMP Snooping на коммутаторах (фильтрация нежелательного multicast-трафика) |
| Multicast-флуд (забивание сети широковещательным трафиком) | Ограничение количества multicast-групп на интерфейсе |
