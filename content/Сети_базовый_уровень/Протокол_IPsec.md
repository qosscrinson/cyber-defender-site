# Протокол_IPsec

> [!abstract] Кратко
> Набор протоколов для безопасной передачи данных по IP-сетям. Обеспечивает шифрование, аутентификацию и целостность на сетевом уровне (L3).

## 1. Зачем нужно
Для построения VPN. Защищает данные от перехвата, подделки и повторной отправки. Работает прозрачно для любых протоколов верхнего уровня (TCP, UDP). **Прозрачность:** IPsec работает на уровне IP (L3). Приложения и протоколы TCP/UDP не знают о шифровании и не требуют изменения кода.

## 2. Простыми словами
Это бронированный сейф для твоих пакетов. Он едет по обычной дороге (Интернету), но никто не может заглянуть внутрь или подменить содержимое. Если сейф вскроют — ты сразу узнаешь.

## 3. Технические детали
- **Компоненты:**
    - **AH (Authentication Header):** аутентификация и целостность. **Не шифрует.**
    - **ESP (Encapsulating Security Payload):** аутентификация + **шифрование**. Самый популярный.
- **Режимы работы:**
    - **Транспортный:** защищает только полезную нагрузку (данные). IP-заголовок открыт. Для связи хост-хост.
    - **Туннельный:** шифрует весь пакет (включая IP-заголовок) и упаковывает в новый. Для связи сеть-сеть (VPN).
- **Управление ключами:** IKE (Internet Key Exchange). Создаёт Security Associations (SA).

## 4. Пример / команда
Проверка статуса IPsec в Linux:

```bash
ip xfrm state
ip xfrm policy
```

## 5. Для ИБ

| Риск | Защита |
|------|--------|
| Использование устаревших алгоритмов (слабые шифры) | Настройка только актуальных алгоритмов (AES-GCM, SHA-256) |
| Проблемы с NAT (IPsec ломается при прохождении через NAT) | Использование NAT-T (NAT Traversal), инкапсуляция в UDP |
| Сложность настройки (человеческий фактор) | Использование проверенных шаблонов конфигурации |
