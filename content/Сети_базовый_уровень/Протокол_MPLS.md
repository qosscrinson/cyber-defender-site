# Протокол_MPLS

> [!abstract] Кратко
> Технология высокоскоростной коммутации пакетов на основе меток (labels). Используется преимущественно провайдерами для быстрой маршрутизации и построения VPN.

## 1. Зачем нужно
Для ускорения передачи данных в ядре сети (маршрутизаторы не смотрят на IP-адреса, а просто меняют метки) и для создания изолированных виртуальных сетей (L2VPN/L3VPN) через общую инфраструктуру.

## 2. Простыми словами
Представь, что на почте сортировщик не читает полный адрес, а клеит на посылку штрихкод (метку). На каждом перевалочном пункте старый штрихкод снимают и клеят новый, указывающий путь до следующего пункта. Так гораздо быстрее, чем заново вчитываться в адрес.

## 3. Технические детали
- **LER (Label Edge Router):** граница MPLS-сети. Клеит метку на входе, снимает на выходе (аналог: таможенный пост).
- **LSR (Label Switch Router):** ядро сети. Только меняет метки по таблице (аналог: сортировочный центр на трассе).
- **LSP (Label Switched Path):** сквозной маршрут, проложенный по меткам (аналог: номер трассы).
- **FEC (Forwarding Equivalence Class):** группа пакетов, обрабатываемых одинаково (например, «весь VoIP-трафик едет по метке 50»).
- **LIB / LFIB:** база данных (справочник) и рабочая таблица коммутации, по которой роутер принимает решения в моменте.
- **Penultimate Hop Popping (PHP):** предпоследний роутер снимает метку, чтобы выездной (граничный) роутер не тратил на это время.
- **Режимы:** Unsolicited (метки раздают заранее, быстро) и on Demand (по запросу, экономно).

## 4. Пример / команда
Просмотр MPLS-меток на интерфейсе (Cisco):

```text
show mpls interfaces
show mpls forwarding-table
```

## 5. Для ИБ

| Риск | Защита |
|------|--------|
| Сложность мониторинга (трафик внутри MPLS-облака не виден стандартными IDS) | Использование NetFlow / sFlow на граничных роутерах (PE) |
| Отсутствие шифрования (MPLS сам по себе не шифрует данные) | Инкапсуляция IPsec поверх MPLS (если это критично) |
