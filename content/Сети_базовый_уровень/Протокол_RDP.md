# Протокол RDP (Remote Desktop Protocol)

> [!abstract] Кратко
> Протокол удаленного управления Windows. Работает на прикладном уровне (L7), использует порт TCP 3389. Позволяет видеть рабочий стол и управлять удаленным ПК. Ключевой вектор атак (брутфорс, BlueKeep) и главные методы защиты (VPN, MFA).

## 1. Зачем нужно
Для администрирования серверов и удаленной работы. Для аналитика SOC (L1) понимание RDP критично, так как это один из самых популярных каналов для первоначального проникновения в сеть (Initial Access) и распространения программ-вымогателей (Ransomware).

## 2. Простыми словами
Это как "удаленный рабочий стол". Ты подключаешься к другому компьютеру через интернет и видишь его экран, можешь двигать мышкой и печатать. Удобно для админов, но очень опасно, если оставить открытым в интернет — злоумышленники будут круглосуточно подбирать туда пароль.

## 3. Технические детали

### 3.1. Основы работы
- **Порт:** TCP 3389 (также может использоваться UDP 3389).
- **Уровень OSI:** Прикладной (L7).
- **Клиент:** В Windows встроен (`mstsc`).
- **Шифрование:** Изначально использовался собственный алгоритм, сейчас стандартом является TLS/CredSSP.

### 3.2. Аутентификация
- **NLA (Network Level Authentication):** Современный стандарт. Требует аутентификации *до* того, как будет создана полноценная сессия RDP. Защищает от многих атак на этапе подключения.

### 3.3. Основные уязвимости и векторы атак
1. **RDP Brute-force (Подбор паролей):** Самый частый сценарий. Боты сканируют интернет, находят открытые 3389 порты и перебирают пароли (admin/123456 и т.д.).
2. **BlueKeep (CVE-2019-0708):** Критическая уязвимость в старых версиях Windows (XP, 7, Server 2008), позволяющая выполнить код без аутентификации (RCE).
3. **Man-in-the-Middle (MITM):** Если нет должного шифрования или сертификатов, трафик могут перехватить.
4. **Ransomware:** После взлома RDP злоумышленники часто разворачивают шифровальщики (например, Ryuk, Phobos).

## 4. Пример / команда

Запуск клиента RDP в Windows:
```cmd
mstsc
```

Диагностика и проверка порта RDP (из командной строки):
```bash
# Проверка доступности порта через Telnet
telnet 192.168.1.100 3389

# Поиск открытых RDP портов через Nmap (для пентеста)
nmap -p 3389 -sV 192.168.1.0/24
```

Просмотр логов подключений (Windows Event Viewer):
- **Event ID 4625:** Неудачная попытка входа (провал брутфорса).
- **Event ID 4624:** Успешный вход.
- **Event ID 1149:** Пользователь прошел аутентификацию NLA (успешно инициирована сессия).

## 5. Для ИБ

| Риск | Защита |
|------|--------|
| Брутфорс (подбор пароля) | Использование сложных паролей, включение MFA, автоматическая блокировка (Account Lockout Policy) |
| Прямой доступ из интернета | Спрятать RDP за VPN или шлюзом (RD Gateway), ограничить по IP (Firewall) |
| Атаки на старые версии (BlueKeep) | Своевременное обновление ОС (Patch Management), отключение RDP на старых машинах |
| Перехват трафика (MITM) | Использование NLA, проверка сертификатов RDP, туннелирование через VPN |
| Использование стандартного порта | Смена порта 3389 на нестандартный (снижает шум от ботов, но не является полноценной защитой) |
