# Протокол_SCTP

> [!abstract] Кратко
> Транспортный протокол (L4), разработанный для объединения лучших черт TCP (надёжность) и UDP (скорость, сохранение границ сообщений). Ориентирован на сообщения, а не на поток байтов.

## 1. Зачем нужно
Для критичных систем, где важна и надёжность, и устойчивость к сбоям сети. Используется в телекоммуникациях (VoIP, SS7) и банковских системах.

## 2. Простыми словами
Это «гибрид» TCP и UDP. Он гарантирует доставку, но при этом передаёт целые сообщения (а не просто куски байтов) и умеет переключаться между разными маршрутами, если один упал.

## 3. Технические детали
- **Уровень:** L4 (транспортный).
- **Ключевые особенности:**
    - **Мультипоточность:** несколько независимых потоков в одном соединении (блокировка одного не тормозит другие). SCTP работает с **сообщениями**, а не с потоком байтов. Внутри одного соединения (ассоциации) он создаёт несколько **независимых логических потоков (streams)**.
        - Поток 1: передаёт картинку.
        - Поток 2: передаёт текст.
        Если в Потоке 1 теряется пакет, SCTP останавливает только Поток 1. Поток 2 продолжает передавать данные без задержек. Приложение получает текст, пока картинка докачивается.
    - **Мультихоминг:** несколько IP-адресов на узел. При отказе маршрута — автоматическое переключение. У сервера есть два IP: основной (через провайдера А) и резервный (через провайдера Б). У клиента тоже есть два IP: Wi-Fi и 4G. При установке соединения SCTP договаривается об этих адресах. Он выбирает **основной путь (Primary path)**. Пока соединение живо, SCTP периодически шлёт по нему специальные проверочные пакеты — **Heartbeat (проверка пульса)**. Если основной путь падает (обрыв кабеля, сбой провайдера), SCTP мгновенно видит, что пульс пропал, и **автоматически переключается на резервный IP-адрес**. Соединение при этом не рвётся, сессия не прерывается. Приложение даже не замечает подмены.
    - **Управление соединениями:** Four-way handshake (устойчивость к SYN-flood).
    - **Контроль целостности:** 32-битный CRC (у TCP — 16 бит).
    - **Передача сообщений:** целые сообщения (Messages), а не поток байтов.
- **Структура пакета:** Common Header (порты, Verification Tag, Checksum CRC32) + Chunks (тип, флаги, длина, данные).
- **PDU:** сообщение (Message) / чанк (Chunk).

**Почему это не взлетело повсеместно?**

SCTP требует, чтобы **и клиент, и сервер** поддерживали эти механизмы. Для этого нужна поддержка на уровне операционных систем, драйверов и сетевого оборудования (роутеров, NAT). В интернете, где всё строится вокруг IP-адресов и TCP, внедрить SCTP массово — это перестраивать половину инфраструктуры. Поэтому он остался в нишевых решениях (телеком, банки).

## 4. Пример / команда
В Windows и Linux обычно не используется для базовых настроек. Требует специфического ПО для мониторинга (например, на базе Diameter).

## 5. Для ИБ

| Риск | Защита |
|------|--------|
| Сложность фильтрации (не все фаерволы умеют разбирать SCTP) | Использование NGFW с поддержкой SCTP, настройка фильтрации по чанкам |
| Использование в обходных путях (редкий протокол может проскочить мимо стандартных правил) | Явное блокирование SCTP на периметре, если он не используется |
