# Протокол_TCP

> [!abstract] Кратко
> Транспортный протокол (L4) с установлением соединения. Гарантирует надёжную, упорядоченную и безошибочную доставку данных (сегментов).

## 1. Зачем нужно
Для приложений, где важна целостность данных: загрузка файлов, веб-сайты (HTTP/HTTPS), почта. Если пакет потерялся — TCP заметит это и отправит его заново.

## 2. Простыми словами
Это как телефонный разговор. Сначала ты говоришь «Алло» (устанавливаешь связь), потом обсуждаешь дела, и в конце обязательно прощаешься. Если связь прервалась, ты перезваниваешь, чтобы уточнить потерянную информацию.

## 3. Технические детали
- **Уровень:** L4 (транспортный).
- **Тип:** с установлением соединения (connection-oriented).
- **Установка (Three-way handshake):**
    1. Отправитель → `SYN`.
    2. Получатель → `SYN-ACK`.
    3. Отправитель → `ACK`.
- **Передача:** механизм подтверждений. Получатель шлёт номер следующего ожидаемого сегмента. Если нет подтверждения (таймаут) — сегмент отправляется заново. После нескольких неудач сессия разрывается.
- **Завершение (Four-way handshake):**
    1. Отправитель → `FIN`.
    2. Получатель → `ACK`.
    3. Получатель → `FIN`.
    4. Отправитель → `ACK`.
- **PDU:** сегмент (Segment).

## 4. Пример / команда
Просмотр активных TCP-сессий:

```bash
netstat -ant
```

## 5. Для ИБ

| Риск | Защита |
|------|--------|
| SYN-флуд (переполнение таблицы соединений полуоткрытыми сессиями) | SYN cookies, таймауты на межсетевых экранах |
| TCP-спуфинг (подмена IP-адреса отправителя для обхода фильтров) | Случайная генерация ISN (начальных последовательностей), использование шифрования |
| Перехват сессии (Session Hijacking) | Использование TLS, аутентификация на уровне приложений |
