# Протокол TCP (углублённо)

> [!abstract] Кратко
> Надёжный транспортный протокол (L4) с установкой соединения. Гарантирует доставку и порядок данных. Использует 3-way handshake, скользящее окно, управление потоком (защита получателя) и управление перегрузкой (защита сети).

## 1. Зачем нужно
IP-протокол работает по принципу «отправил и забыл» (best effort). TCP берёт на себя надёжность: разбивает данные на сегменты, нумерует их, подтверждает получение, пересылает потерянное и собирает в правильном порядке.

## 2. Простыми словами
Это как телефонный разговор. Ты звонишь (SYN), тебе отвечают (SYN-ACK), ты подтверждаешь (ACK). Только потом вы говорите. Когда закончили — прощаетесь (FIN/ACK). Если связь оборвалась — просто кладёте трубку (RST).

## 3. Технические детали

### 3.1. Установка и разрыв
- **3-way handshake:** SYN (отправитель) → SYN-ACK (получатель) → ACK (отправитель). Синхронизируются случайные начальные номера байт.
- **Разрыв:** плавный (обмен FIN/ACK) или жёсткий (флаг RST для мгновенного сброса).

### 3.2. Формат заголовка (ключевые поля)
- **Порты (16 бит):** отправитель и получатель.
- **Sequence Number:** номер первого байта в сегменте.
- **Acknowledge Number:** номер байта, который ждём.
- **Флаги (UAPRSF):** URG, ACK, PSH, RST, SYN, FIN.
- **Window Size:** сколько байт готовы принять.

### 3.3. Управление потоком (Flow Control)
- **Проблема:** отправитель может «затопить» получателя.
- **Решение:** скользящее окно (Sliding Window). Получатель в поле Window указывает, сколько байт он готов принять.
- **SACK (Selective ACK):** позволяет указать конкретные полученные диапазоны, чтобы переслать только потерянное, не дублируя всё остальное.

### 3.4. Управление перегрузкой (Congestion Control)
- **Проблема:** сеть (маршрутизаторы) не справляется с потоком.
- **Решение:** окно перегрузки (Congestion Window). Алгоритм **AIMD** (Additive Increase, Multiplicative Decrease).
- **Медленный старт:** экспоненциальный рост окна. При потере пакета — окно срезается вдвое (Multiplicative Decrease).

## 4. Пример / команда
Просмотр соединений и анализ в Wireshark:

```bash
ss -tulnp
netstat -ano
```

Фильтры Wireshark: `tcp.flags.syn == 1` (установка), `tcp.analysis.retransmission` (потери).

## 5. Для ИБ

| Риск | Что делает атакующий | Защита |
|------|----------------------|--------|
| SYN Flood (DDoS) | Шлёт тысячи SYN, не завершая рукопожатие. Сервер держит полуоткрытые соединения, пока не кончится память. | SYN-cookies, лимиты на полуоткрытые соединения, анти-DDoS. |
| TCP Hijacking (MITM) | Угадывает Sequence Number и вставляет свои данные, разрывая связь жертвы (RST). | Шифрование (TLS/SSH), рандомизация ISN, IPS. |
| RST-инъекция | Поддельный RST-пакет для обрыва соединения (например, VPN). | Шифрование, проверка подлинности. |
| Сканирование портов | SYN-скан (Nmap) для поиска открытых служб. | Закрыть неиспользуемые порты, IDS/IPS. |

**Главная мысль:** TCP гарантирует доставку, но не защищает содержимое. Защита начинается выше (TLS).
