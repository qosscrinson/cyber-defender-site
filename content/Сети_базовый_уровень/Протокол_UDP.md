# Протокол_UDP

> [!abstract] Кратко
> Транспортный протокол (L4) без установления соединения. Обеспечивает быструю передачу данных (датаграмм) с минимальными задержками, но без гарантий доставки.

## 1. Зачем нужно
Для приложений, где скорость важнее надёжности (стриминг, онлайн-игры, DNS). Если пакет потерялся — UDP не будет его пересылать, приложение просто продолжит работу.

## 2. Простыми словами
Это как отправить открытку по почте. Ты кинул её в ящик и пошёл дальше. Ты не знаешь, дойдёт ли она, не проверяешь трек-номер, и если она потеряется, почта не будет отправлять её заново.

## 3. Технические детали
- **Уровень:** L4 (транспортный).
- **Тип:** без установления соединения (connectionless).
- **Характеристики:**
    - Нет гарантии доставки.
    - Нет гарантии порядка (пакеты могут прийти вразнобой).
    - Нет гарантии целостности.
    - Не сохраняет состояние.
    - Контроль целостности только через контрольную сумму (если она равна `0` в IPv4 — значит, не используется).
- **Структура:** заголовок 8 байт (порты, длина, контрольная сумма). Максимальный размер IP-дейтаграммы — 65535 байт.
- **PDU:** датаграмма (Datagram).

## 4. Пример / команда
Проверка открытых UDP-портов:

```bash
netstat -anu
```

## 5. Для ИБ

| Риск | Защита |
|------|--------|
| UDP-флуд (DDoS-атака за счёт отправки множества UDP-пакетов) | Rate limiting на межсетевых экранах, фильтрация неиспользуемых портов |
| Подмена DNS-ответов (так как UDP не проверяет подлинность отправителя) | Использование DNSSEC, DNS-over-HTTPS (DoH) |
