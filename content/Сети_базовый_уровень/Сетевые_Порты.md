# Сетевые порты

> [!abstract] Кратко
> Числовые идентификаторы (от 0 до 65535), которые операционная система использует для направления сетевого трафика к конкретным приложениям. IP-адрес ведет к компьютеру, а порт — к программе на этом компьютере.

## 1. Зачем нужно
На одном сервере одновременно работают веб-сервер, почтовый сервер и SSH. Все они имеют один IP-адрес. Порты позволяют понять, какому именно приложению предназначен пришедший пакет. Для SOC-аналитика порт — это маркер сервиса и потенциальной уязвимости.

## 2. Простыми словами
Представь, что IP-адрес — это адрес многоквартирного дома (например, ул. Ленина, д. 15). А сетевой порт — это номер квартиры. Чтобы письмо дошло до конкретного жильца (программы), нужно знать не только адрес дома, но и номер квартиры (порт 80 — веб-сервер, порт 3389 — RDP).

## 3. Технические детали

### 3.1. Диапазоны портов
- **0 – 1023 (Well-known):** Системные порты. Зарезервированы за популярными службами (HTTP, HTTPS, DNS, SSH).
- **1024 – 49151 (Registered):** Зарегистрированные порты (например, 3389 для RDP, 8080 для альтернативного веба).
- **49152 – 65535 (Dynamic / Private):** Динамические порты. ОС выбирает их случайным образом для исходящих соединений клиента (например, когда ты открываешь браузер).

### 3.2. Ключевые порты (шпаргалка для SOC)

| Порт | Протокол | Транспорт | Назначение |
|---|---|---|---|
| 20/21 | FTP | TCP | Передача файлов (незащищенная) |
| 22 | SSH | TCP | Безопасное удаленное управление (Linux) |
| 23 | Telnet | TCP | Удаленное управление (устаревшее, без шифрования) |
| 25 / 587 | SMTP | TCP | Отправка почты |
| 53 | DNS | UDP/TCP | Разрешение доменных имен (UDP для запросов, TCP для зон) |
| 67/68 | DHCP | UDP | Автоматическая выдача IP-адресов |
| 80 | HTTP | TCP | Веб-трафик (без шифрования) |
| 443 | HTTPS | TCP | Веб-трафик (с шифрованием TLS) |
| 445 | SMB | TCP | Сетевые папки Windows (частый вектор атак) |
| 3389 | RDP | TCP | Удаленный рабочий стол Windows |

### 3.3. Как работает маршрутизация по портам
1. Клиент (браузер) инициирует соединение из **динамического порта** (например, `52140`).
2. Пакет отправляется на **стандартный порт** сервера (например, `443`).
3. ОС сервера видит: «Пакет пришел на порт 443, а его слушает веб-сервер (Nginx). Отдаю его ему».

## 4. Пример / команда

Посмотреть, какие порты открыты и слушаются на твоем устройстве:
```bash
# Linux (покажет порты, программы и PID)
ss -tulpn

# Windows (покажет активные подключения и состояния LISTENING)
netstat -ano | findstr LISTENING
```

Проверка конкретного порта на удаленном хосте (например, открыт ли RDP):
```bash
# Через telnet
telnet 192.168.1.1 3389
```

## 5. Для ИБ

| Риск | Защита |
|------|--------|
| Сканирование портов (Port Scan) | Firewall (закрыть все лишние порты), IDS/IPS (детект сканирования) |
| Открытые в интернет опасные порты (RDP 3389, SMB 445, SSH 22) | Запретить прямой доступ извне, использовать VPN или шлюзы |
| Использование нестандартных портов (например, бэкдор на 4444) | Мониторинг аномалий (NTA/SIEM), белые списки портов |
| Ransomware через SMB (445) | Отключение SMBv1, патчинг, сегментация сети |
