# Сравнение_Clos_Fat_Trees

> [!abstract] Кратко
> Clos — масштабируемость, экономия, стандарт ЦОД. Fat-Trees — минимальная задержка, дорого, для HPC. В реальных сетях — гибрид: трехуровневая модель + Clos для доступа к серверам + DMZ.

## 1. Зачем нужно
Одна таблица вместо двух заметок — быстро выбрать топологию под задачу.

## 2. Простыми словами
Clos — «город с объездными»: дёшево, гибко, чуть медленнее. Fat-Trees — «выделенные трассы»: быстро, но дорого.

## 3. Технические детали

| Критерий | Clos | Fat-Trees |
|---|---|---|
| **Масштабируемость** | Легко (добавление spine) | Сложно (избыточные соединения) |
| **Стоимость** | Экономичнее | Дороже |
| **Задержка** | Стабильная, но выше | Минимальная |
| **Использование** | ЦОД, облака | HPC, суперкомпьютеры |

**Почему Clos доминирует в ЦОДах:**

- гибкость — начать с малого, наращивать;
- простота — BGP/OSPF «из коробки»;
- экономия — оптические линки 100G дешевле тысяч кабелей.

**Когда что выбирать:**

- **Clos** — масштабируемая экономичная сеть для облака/веб-сервисов;
- **Fat-Trees** — максимальная производительность для научных вычислений.

**Гибрид:** классическая трехуровневая модель + Clos для доступа к серверам + DMZ для безопасности.

## 4. Пример / команда
Проверка текущей топологии:

```bash
show ip route
show ip bgp summary
```

## 5. Для ИБ

| Риск | Защита |
|------|--------|
| Выбор «по привычке» → неоптимально | Критерии: масштаб, бюджет, задержка |
| Гибрид без документации → путаница | Схема: где Clos, где трехуровневая |
| Нет DMZ → публичные сервисы в LAN | DMZ + firewall |
| Нет ACL между топологиями | Микросегментация |
