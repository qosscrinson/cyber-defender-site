# Туннелирование

> [!abstract] Кратко
> Технология инкапсуляции пакетов одного протокола в пакеты другого для передачи через сети, которые не поддерживают исходный протокол (или для обеспечения безопасности).

## 1. Зачем нужно
Позволяет передавать трафик через несовместимые или небезопасные сети. Например, передать IPv6 через IPv4 или защитить корпоративный трафик при передаче через публичный интернет.

## 2. Простыми словами
Это как отправить письмо в конверте. Твое письмо (исходные данные) не может само дойти через почту. Ты кладешь его в стандартный конверт (новый заголовок), почта несет его, а на другом конце получатель достает письмо (декапсуляция).

## 3. Технические детали
*   **Этапы:**
    1. **Инкапсуляция:** Исходный пакет упаковывается в новый заголовок.
    2. **Передача:** Упакованный пакет идет через сеть.
    3. **Декапсуляция:** На конечном узле пакет распаковывается.
*   **Виды:**
    *   **Прозрачное:** Пакеты передаются без изменений (например, 6to4).
    *   **Изменяющее:** Включает шифрование или преобразование (например, VPN).

## 4. Пример / команда
Настройка туннеля (общий пример):
```bash
ip tunnel add tun0 mode gre remote 10.0.0.2 local 10.0.0.1
```

## 5. Для ИБ

| Риск | Защита |
|------|--------|
| **Туннелирование в обход фаервола** (злоумышленник прячет вредоносный трафик) | DPI (Deep Packet Inspection) для проверки содержимого туннелей |
| **Отсутствие шифрования** (если используется прозрачное туннелирование) | Использование защищенных протоколов (IPsec, TLS) поверх туннелей |
